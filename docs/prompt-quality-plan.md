# 요약 프롬프트 품질 계획 (10/1 세움, 아직 시험 전)

요약 호출의 프롬프트(`app/src/core/prompts.ts`의 `SUMMARY_UNIFIED`)를 다듬기 위한 기준, 시험 방법, 분량 시험용 프롬프트 초안이다. 전사문 다듬기(`POLISH_TRANSCRIPT`)는 선택 기능이고 비용이 커서 요약 뒤로 미룬다.

이 문서의 숫자 가운데 통과선과 비용은 어림이다. 시험 결과는 `docs/decisions.md`에 적는다.

## 왜 재는 방법부터인가

10/1 시험(`decisions.md` "요약 프롬프트 시험")에서 같은 프롬프트로 같은 강의를 4번 돌린 요약 점수가 70~83%로 흔들렸고, 프롬프트 간 차이(3점)는 그 안에 묻혔다. 조건마다 반복 횟수가 달랐고(2~4회), 규칙과 예시를 함께 바꿔 어느 쪽 효과인지 가르지 못했다.

## 누구를 위한 결과물인가

주 사용자는 강의를 듣는 대학생이고 복습에 쓴다. 노트를 여는 상황:

1. 그 강의에서 뭘 배웠는지 빨리 떠올리기
2. 시험 공부할 때 개념·정의·예시 찾기
3. 강의 자료나 교재에서 같은 용어 찾기 (자료는 대개 영어 표기)

과제·시험 공지는 요약에 넣지 않는다(작성자 결정).

## 기준

기준이 부딪히면 이 순서로 정한다: **틀린 내용 없음 > 빠짐없음 > 설명 있음 > 나머지**.

### 요약

| 기준 | 구체적으로 | 재는 법 |
|---|---|---|
| 틀린 내용 없음 | 강의에 없는 내용, 뜻이 뒤집힌 설명 수 | 기준 전사와 대조 |
| 빠짐없음 | 체크리스트(강의당 13~18개) 항목 포함률 | 조건을 가리고 채점 |
| 설명 있음 | 들어간 항목 중 이름만 나열하지 않고 "무엇이고 왜"가 붙은 비율 | 항목마다 이름만 / 설명 있음 |
| 용어를 자료에서 찾을 수 있음 | 영어에서 온 전문용어가 처음 나올 때 `파싱(Parsing)`처럼 함께 적힌 비율. 필기에 있으면 필기 표기와 일치. 영어 철자가 틀린 수 | 체크리스트 용어로 셈 |
| 구체적 예시 | 강의의 예시·숫자·비교가 들어간 수 | 셈 |
| 훑어보기 쉬움 | 주제별로 나뉘어 있는지, 굵게 표시가 실제 핵심어인지 | 3단계 평가 |
| 분량 | 글자 수 | 코드 |

### 교정

교정은 전사문에 문자열 바꾸기로 그대로 적용된다. "표기를 바꿨는가"가 아니라 "뜻을 망가뜨렸는가"로 판정한다.

| 갈래 | 예 | 점수 |
|---|---|---|
| 뜻을 바로잡음 | 데드랙 → 데드락 | 이득 |
| 표기만 바꿈 | 코사인 → cos | 중립 (세지 않음) |
| 망가뜨림 | 맞는 말을 틀린 말로, 다른 단어 안까지 바뀜(비 → B) | 손해 |

지표:

- 망가뜨린 수 (회당, 0에 가깝게)
- 뜻을 바로잡은 수 (회당, 많을수록 좋음)
- 놓친 오인식 수: 기준 전사와 비교해 전문용어가 틀린 채 남은 곳. 지금까지 세지 않던 것이다.

기존 "맞게 고친 비율"은 표기만 바꾼 것을 감점하므로 쓰지 않는다. 기존 판정표의 "표기만 바꿈"은 중립으로 옮기면 되고 다시 판정할 필요는 없다.

### 키워드

- 체크리스트의 핵심 용어 중 들어간 수
- 너무 일반적인 말("개념", "예시")이 섞인 수
- 개수 (5~10개)

### 형식 (코드로 셈)

- JSON 파싱 실패율 (0이어야 함). 요약이 길고 줄바꿈이 많아질수록 깨질 수 있어 분량 시험에서 꼭 본다.
- 전사에 없는 `wrong`의 비율

## 시험 틀

- **강의를 개발용과 확인용으로 나눈다.** 2차 비교의 4개는 예시를 고를 때 이미 들여다봤으니 개발용. 프롬프트를 고칠 때 보지 않을 강의 2~3개를 확인용으로 따로 둔다(다른 과목이면 더 좋다).
- **반복 횟수를 고정한다.** 조건마다 강의당 같은 횟수. 차이가 반복 간 흔들림보다 클 때만 채택한다.
- **한 번에 하나만 바꾼다.**
- 모델은 기본값 gpt-6-luna. 채택 후보만 gemini-3.8-flash로 한 번 확인한다.
- 코드로 세는 지표는 스크립트로 매번, 사람이 판정하는 지표는 채택 후보에만.
- 요약문·채점표·판정표는 강의 내용이라 저장소 밖에 둔다(데스크톱 `s3-data\9.30 전사 품질 실험\prompt-ab\` 옆).

## 순서

1. 채점 스크립트와 판정 틀을 위 기준으로 고친다 (교정 세 갈래, 놓친 오인식, 용어 병기 비율, 설명 있음).
2. **분량 시험**으로 요약의 틀을 정한다 (아래).
3. 정한 틀에서 실패 사례를 유형별로 세고, 많은 것부터 한 가지씩 고친다. 첫 후보: 10/1에 넣은 "표기만 바꾸는 교정 금지" 규칙과 그 예시를 빼고 "한 글자 금지"만 남기는 판(새 기준에서 그 규칙은 이득이 아닌데 요약이 12% 짧아졌다).
4. 확인용 강의로 검증하고 앱에 넣는다. 수정안·숫자·버린 안을 `decisions.md`에 적는다.

## 분량 시험

분량은 요약의 틀을 바꾸므로 다른 수정보다 먼저 정한다.

| 안 | 모양 | 어림 분량(90분 강의) |
|---|---|---|
| A0 | 지금 프롬프트 그대로 (기준선) | 약 900자 |
| A | 지금 + 용어 병기: 5~10문장 한 덩어리 | 약 900자 |
| B | 개요 한두 문장 + 주제별 굵은 소제목 아래 2~3문장 | 약 1,500~2,000자 |
| C | 개요 한두 문장 + 주제별 굵은 소제목 아래 목록(개념: 설명 한 줄) | 약 1,500자 |
| D | B를 주제마다 4~6문장으로, 예시까지 풀어 씀 | 약 3,000자 |

A0와 A의 차이는 용어 병기 규칙 하나, A~D의 차이는 `summary` 설명 하나다. 교정 규칙은 다섯 안 모두 지금 그대로 둔다(3단계에서 따로 본다).

고르는 법. 길면 포함률은 당연히 오르므로 포함률만 보지 않는다.

1. 틀린 내용 수가 A보다 늘어난 안은 탈락. JSON 파싱이 한 번이라도 실패한 안도 탈락.
2. 포함률과 설명 있는 비율이 분량 대비 얼마나 오르는지 본다.
3. 남은 안은 작성자가 직접 고른다: 본인이 들은 강의 2~3개의 요약을 어느 안인지 가린 채 받아, 복습에 쓰고 싶은 순서로 줄 세운다.

규모: 개발용 4개 × 5안 × 3회 = 60회. luna가 회당 약 4.3크레딧이었으니 약 260, 긴 안의 출력을 더해 300크레딧 안쪽으로 어림한다.

함께 확인할 것:

- 노트 파일과 앱 미리보기에서 소제목·목록이 들어간 요약이 어떻게 보이는지. 소제목은 `##`가 아니라 굵게로 써서 노트의 제목 구조와 부딪히지 않게 했다.
- 옵시디언의 굵게 문제(`CLAUDE.md` "사용자가 할 것" 3번): `**파싱(Parsing)**을`처럼 닫는 `**` 앞이 괄호이고 뒤에 조사가 붙으면 옵시디언에서 굵게가 안 된다. 용어 병기는 이 모양을 늘린다. 초안에서는 굵게를 한글 용어에만 걸고 괄호를 밖에 두게 했다(`**파싱**(Parsing)을`). 실제로 지켜지는지 출력에서 센다.
- `keywords`의 표기는 이번에 바꾸지 않는다(노트 머리말·태그에 쓰여 괄호가 들어가면 안 될 수 있음).

## 프롬프트 초안

`SUMMARY_UNIFIED`에서 바뀌는 곳은 두 군데다. 나머지 줄은 지금 그대로 쓴다.

### 공통: 용어 병기 규칙 (A~D, "요약 규칙:" 목록 끝에 더함)

```
- 영어에서 온 전문용어는 요약에서 처음 나올 때 한글 표기 뒤에 괄호로 영어를 함께 적으세요 (예: 파싱(Parsing), 뮤텍스(Mutex)). 같은 용어가 다시 나오면 한글만 적으세요. 필기노트에 그 용어가 있으면 필기노트의 표기를 그대로 쓰세요. 영어 철자에 확신이 없으면 한글만 적으세요.
- 용어를 굵게 표시할 때는 한글 용어에만 **를 걸고 괄호는 밖에 두세요 (예: **파싱**(Parsing)은).
```

### 안별: JSON 형식의 `summary` 설명

A (지금과 같음):

```
"summary": "강의 전체 내용을 학생이 나중에 복습할 때 도움이 되도록 5~10문장으로 요약. 핵심 개념과 논리 흐름 위주로 작성. 마크다운 문법(굵게, 목록 등) 자유롭게 사용 가능.",
```

B (주제별 문단):

```
"summary": "학생이 나중에 복습할 때 쓰는 요약. 첫 문단은 강의 전체를 한두 문장으로 정리한 개요. 그 뒤로 강의에서 다룬 주제마다 한 문단씩, 강의 순서대로 씁니다. 주제 문단은 굵게(**) 쓴 주제 이름 한 줄로 시작하고, 다음 줄부터 그 주제의 핵심 개념이 무엇이고 왜 그런지를 2~3문장으로 설명합니다. 주제 수는 강의 내용에 맞추되 보통 3~7개. 문단 사이는 빈 줄. 제목 문법(#)은 쓰지 마세요.",
```

C (주제별 목록):

```
"summary": "학생이 나중에 복습할 때 쓰는 요약. 첫 문단은 강의 전체를 한두 문장으로 정리한 개요. 그 뒤로 강의에서 다룬 주제마다 한 묶음씩, 강의 순서대로 씁니다. 묶음은 굵게(**) 쓴 주제 이름 한 줄로 시작하고, 그 아래에 목록(- )으로 개념마다 한 줄씩 '개념: 무엇이고 왜 그런지 한 문장'을 적습니다. 묶음 하나에 목록 2~5줄, 주제 수는 강의 내용에 맞추되 보통 3~7개. 묶음 사이는 빈 줄. 제목 문법(#)은 쓰지 마세요.",
```

D (주제별 긴 문단):

```
"summary": "학생이 이 요약만 읽고도 강의 내용을 다시 공부할 수 있게 쓰는 자세한 요약. 첫 문단은 강의 전체를 한두 문장으로 정리한 개요. 그 뒤로 강의에서 다룬 주제마다 한 문단씩, 강의 순서대로 씁니다. 주제 문단은 굵게(**) 쓴 주제 이름 한 줄로 시작하고, 다음 줄부터 4~6문장으로 핵심 개념의 정의, 그렇게 되는 이유, 강의에서 든 예시나 숫자를 설명합니다. 주제 수는 강의 내용에 맞추되 보통 3~7개. 문단 사이는 빈 줄. 제목 문법(#)은 쓰지 마세요.",
```

### B~D에서 함께 손볼 기존 줄

- "요약을 추상적인 개념 나열로 끝내지 말고 … 구체적인 예시를 최소 1~2개 포함" → B·C는 그대로, D는 "주제마다 하나 이상"으로.
- "요약 안에서 굵게(**) 표시하며 소제목처럼 개별적으로 설명한 개념은 keywords에서도 … 각각 별도 항목으로" → B~D에서는 굵은 줄이 주제 이름이라 뜻이 달라진다. "주제 안에서 따로 설명한 개념은 keywords에도 각각 넣으세요"로 바꾼다.
- "요약은 교정 규칙과 상관없이 … 짧게 줄이지 마세요" → 분량을 `summary` 설명이 정하므로 B~D에서는 "교정 규칙은 요약의 분량이나 자세함에 영향을 주지 않습니다"로 줄인다.

이 세 줄을 바꾸면 A와 B~D의 차이가 `summary` 설명 하나가 아니게 된다. 틀이 달라져 뜻이 안 맞는 줄만 고친 것이고, 그 밖의 줄은 건드리지 않는다.

## 정해지지 않은 것

- 확인용 강의 2~3개 (녹음·필기, 개발용 4개와 겹치지 않게)
- 채점자: 지금까지 Claude 1인이다. 강의 하나를 작성자가 직접 채점해 Claude 채점과 맞는지 볼지
- 통과선의 숫자: A0 기준선을 잰 뒤 정한다
