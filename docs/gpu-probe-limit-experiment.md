# GPU 재기 한도 실험 (데스크톱)

데스크톱(외장 그래픽카드)에서 Claude Code가 이 문서대로 실험하고 결과를 정리한다. 10/11 노트북 세션에서 만든 계획이다. 배경과 노트북 숫자는 `docs/decisions.md`의 "노트북 스레드별 속도와 모델 비율 (10/11, 노트북)" 절에 있다.

## 왜 하나

속도 재기(`app/src/core/probe.ts`)는 39초 샘플을 CPU로 한 번, GPU 장치마다 한 번 받아쓴다. GPU 쪽은 CPU로 잰 시간의 5배, 적어도 2분이 지나면 그만둔다(`GPU_TRIAL_VS_CPU`, `GPU_TRIAL_MIN_MS`). 노트북의 내장 GPU는 small로 약 57초를 끝까지 돈 뒤 전사가 깨져 버려지고, 그래서 속도 재기 전체가 66초 걸린다.

넣으려는 규칙: **Windows에서는 한도를 max(샘플 길이 39초, CPU로 잰 시간)으로 줄인다. macOS는 지금대로 둔다.**

이 실험으로 확인할 것은 하나다. **쓸 만한 외장 GPU가 새 한도 안에 끝나는가.** 한도는 whisper-cli를 띄운 때부터 재므로 모델 로드와 셰이더(Vulkan 파이프라인) 만드는 시간이 들어간다. 멀쩡한 GPU가 처음 실행에서 39초를 넘기면 이 규칙이 그 GPU를 떨어뜨려 계속 CPU로 돌게 된다.

## 준비 (확인만 하고, 없으면 사용자에게 묻는다)

- `feat/auto-stt-model` 브랜치를 받는다.
- 다른 무거운 프로그램을 끄고, 한 번에 하나만 돌린다. 설치본 Note-crAIte가 받아쓰기 중이면 끝난 뒤에 한다.
- `.cache/whisper/bin/whisper-cli.exe`(Vulkan 빌드), Node 24 이상.
- `cli probe`는 데이터 폴더의 `probe.json`을 덮어쓴다. 시작 전에 복사해 두고 끝나면 되돌린다(아래 명령에 들어 있다). 모델은 데이터 폴더의 것을 쓰고, 없으면 받는다.

## 재는 법

`cli probe`는 장치마다 시작할 때 `<이름> 확인 중...`을 찍고, 모두 끝나면 결과 줄을 한꺼번에 찍는다. 줄마다 시각을 붙여 장치별로 걸린 시간을 읽는다. `app/`에서 PowerShell로 돌린다.

```powershell
$d = "$env:LOCALAPPDATA\lecture-notes"; Copy-Item "$d\probe.json" "$d\probe.json.bak" -Force
```

```powershell
npm run cli -- probe --model small-q5_1 | ForEach-Object { "$(Get-Date -Format HH:mm:ss.fff) $_" }
```

```powershell
npm run cli -- probe --model large-v3-turbo-q8_0 | ForEach-Object { "$(Get-Date -Format HH:mm:ss.fff) $_" }
```

```powershell
Copy-Item "$d\probe.json.bak" "$d\probe.json" -Force
```

읽는 법:

- **CPU로 잰 시간** = `CPU 확인 중...` 줄부터 첫 GPU의 `확인 중...` 줄까지.
- **GPU로 잰 시간** = 그 GPU의 `확인 중...` 줄부터 다음 장치의 `확인 중...` 줄(마지막 장치면 결과 줄)까지. 이 값이 새 한도와 견줄 값이다.
- 결과 줄의 `처리 N초 · 로드 N초`는 whisper가 잰 값이다. GPU로 잰 시간에서 이 둘을 뺀 나머지가 프로세스 시작과 셰이더 만드는 데 든 시간이다.
- 장치가 여럿이면(내장 + 외장) 장치마다 따로 적는다.

## 실험 A: 평소 상태 (필수, 약 10분)

small과 turbo를 세 번씩 돌린다.

| 모델 | 회 | CPU로 잰 시간(초) | GPU 이름 | GPU로 잰 시간(초) | 그중 처리 / 로드(초) | 나머지(초) | 고른 장치 |
|---|---|---|---|---|---|---|---|
| small | 1 | | | | | | |
| small | 2 | | | | | | |
| small | 3 | | | | | | |
| turbo | 1 | | | | | | |
| turbo | 2 | | | | | | |
| turbo | 3 | | | | | | |

## 실험 B: 처음 실행에 가까운 상태 (필수, 사용자가 다시 켠 뒤 약 5분)

그래픽 드라이버는 만든 셰이더를 디스크에 넣어 두므로 두 번째부터는 빨라질 수 있다. 처음 설치한 사람의 상태에 가깝게 보려면 PC를 다시 켠 직후 첫 실행을 잰다.

1. 사용자에게 PC를 다시 켜 달라고 한다(다른 프로그램을 띄우기 전에).
2. turbo로 한 번, 이어서 small로 한 번 돌려 실험 A와 같은 칸을 적는다.

- 드라이버의 셰이더 캐시 폴더를 직접 지우는 것은 하지 않는다(위치를 확인하지 못했고 다른 프로그램에도 영향을 준다). 그래서 이 실험은 "캐시가 전혀 없는 PC"가 아니라 "다시 켠 직후"까지만 본다는 점을 결과에 적는다.
- 사용자가 최근에 그래픽 드라이버를 새로 깔았거나 깔 계획이 있으면 그 직후의 첫 실행이 가장 좋은 자료다.

## 실험 C: CPU가 느린 PC 흉내 (선택, 약 10분)

새 한도는 CPU가 39초보다 느리면 CPU 시간까지 기다린다. 스레드를 줄여 그 경우를 본다.

```powershell
npm run cli -- probe --model large-v3-turbo-q8_0 --threads 2 | ForEach-Object { "$(Get-Date -Format HH:mm:ss.fff) $_" }
```

`--threads 1`로도 한 번 돌린다. CPU로 잰 시간이 39초를 넘는지, 그때도 외장 GPU가 CPU 시간 안에 끝나 뽑히는지 적는다. `--threads`는 GPU로 잴 때의 스레드에도 들어가지만 GPU 처리에는 영향이 작다.

## 판단

외장 GPU로 잰 시간 가운데 가장 큰 값(실험 A·B, 두 모델)을 본다.

| 가장 큰 값 | 판단 |
|---|---|
| 20초 이하 | 새 규칙을 넣길 권한다. 39초의 절반 아래라 느린 외장 GPU에도 여유가 있다 |
| 20~39초 | 39초로는 여유가 모자란다. 한도의 아래쪽을 60초로 두는 안(max(60초, CPU 시간))을 권하거나 넣지 않는다. 노트북에서 줄어드는 시간이 거의 없어진다(57초 → 그대로)는 점을 함께 적는다 |
| 39초 초과 | 넣지 않는다 |

- 실험 B가 A보다 눈에 띄게 길면(셰이더 시간이 큼) 그 차이를 적는다. 캐시가 전혀 없는 PC는 그보다 더 걸릴 수 있다.
- 내장 GPU가 함께 있으면 그 장치가 지금 몇 초를 쓰는지, 새 한도에서 몇 초가 줄어드는지도 적는다.
- 노트북에서의 효과(참고): small의 속도 재기 전체 66초 → 약 48초, turbo는 내장 GPU가 24초에 끝나 그대로.

## 넣는다면 (사용자에게 먼저 묻는다)

코드를 고치지 말고 결과와 권하는 안을 사용자에게 먼저 알린다. 넣기로 하면:

- `probe.ts`의 `gpuLimitMs` 계산을 Windows(`metal`이 아닐 때)는 `Math.max(sampleS * 1000, CPU로 잰 시간)`으로, macOS는 지금 식 그대로 둔다. 위 상수의 주석도 함께 고친다.
- `test/`의 속도 재기 테스트에 한도 계산을 보는 것을 더한다(지금은 `gpuTrialLimitMs`로 한도를 직접 준다).
- 그만둔 이유 문구(`너무 오래 걸려 그만뒀습니다 (N초)`)는 그대로 쓴다.

## 결과 적기

- `docs/decisions.md`의 10/11 절 "GPU 재기를 일찍 그만두는 안" 아래에 데스크톱 결과(위 표, 판단, 한계)를 날짜와 함께 덧붙인다. 넣었으면 "구현 결정" 표에도 한 줄 적는다.
- 한계로 적을 것: 외장 GPU 한 대, 셰이더 캐시가 전혀 없는 상태는 못 봄, 느린 외장 GPU(VRAM 2GB급)는 재지 않음.
- 못 잰 칸은 비워 두지 말고 이유를 적는다.
